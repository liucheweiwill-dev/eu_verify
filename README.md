# eu_verify

檢查 Google 回的結果，關鍵字是**真的在正文裡**，還是**只在導覽列裡**。

搭配 [eu_monitor](../eu_monitor) 用，但**刻意是分開的程式**——
eu_monitor 是單檔、零依賴、零建置的啟動器，它的價值就在於小到不會壞。
這隻工具壞掉時不應該影響你每天按的那顆鈕。
（eu_monitor 的 `docs/AGENT_BRIEF.md` §7 就是這樣規定的。）

## 它做什麼

輸入一份網址清單，輸出一份 `search_result.html`，把每筆分成三類：

| | 意義 |
|---|---|
| **正文確認命中** | 關鍵字在正文裡，附上命中了哪些字、各幾次 |
| **只在導覽列命中** | Google 誤判——那些字只出現在全站共用的選單裡 |
| **無法檢查** | 抓不到（403／逾時／網域不在設定裡）。**既不是命中也不是未命中** |

## 它不做什麼

**這是精確度工具，不是召回工具。**

它只能從 Google 已經給你的清單裡剔除假命中。
**它不會、也不可能告訴你有沒有漏掉東西**——Google 沒回的頁面它永遠看不到。

依 eu_monitor 的核心原則（漏掉比抓錯嚴重得多），這點要一直記得。

## 用法

```bash
node verify.js                      # 讀 urls.txt，寫出 search_result.html
node verify.js my.txt -o out.html   # 自訂輸入輸出
```

需要 Node 18+（用內建 `fetch`）。**零依賴，不用 npm install。**

輸入是純文字檔，一行一個網址，`#` 開頭的行會被忽略。
目前網址要自己從 Google 結果頁複製出來——見下面「還沒做的」。

## 為什麼不能直接 grep 網頁

**因為導覽列的字就在 HTML 裡。**

機構網站的全站選單會把國名與主題名塞進每一頁。直接搜 `Indo-Pacific`，
會在一篇完全沒提印太的人道法演說上命中——因為 EEAS 每一頁的導覽列都有
`<a href="/eu-indo-pacific-strategy-topic_en">EU Indo-Pacific Strategy</a>`。

那正是 Google 犯的錯，直接 grep 只會把同一個錯重做一次。

### 解法：跟該站的 404 頁相減

每個 host 先抓一張不存在的路徑（404 頁）。它**保證沒有正文、但有完整的導覽列**，
是最乾淨的 chrome 基準線。候選頁的命中數要**超過**基準線，才算正文真的有。

實測（數字是同一個關鍵字在該頁出現幾次）：

| 關鍵字 | 候選頁 | 候選 | 基準線 | 判定 |
|---|---|---|---|---|
| `Indo-Pacific` | UN 人道法演說 | 2 | 3 | 只在導覽列 ✓ |
| `Indo-Pacific` | EEAS 印太主題頁 | 72 | 3 | 正文有 ✓ |
| `Taiwan` | UN 人道法演說 | 2 | 2 | 只在導覽列 ✓ |
| `Indo-Pacific` | NATO 印太夥伴頁 | 87 | 4 | 正文有 ✓ |

`urls.txt` 裡放的就是這幾個案例，正確答案已知，改動程式後可以直接跑來對。

## 已知限制

**1. `consilium.europa.eu` 永遠是「無法檢查」。**
該站對所有自動化客戶端回 403（JS 指紋挑戰），連會執行 JS 的自動化瀏覽器
等 18 秒也過不去。這不是 bug，是對方擋的。只有真人手動操作的瀏覽器過得去。

**2. 子網域有自己的導覽列。**
基準線是**按 host** 抓的，所以 `ndc.nato.int` 會用它自己的 404 頁當基準——
這是對的。但如果某個子網域擋掉 404 探測，那個 host 的結果會全部變成「無法檢查」。

**3. soft-404 會讓判定偏嚴。**
有些站對不存在的路徑回 200 加真實內容。那樣基準線會被灌水，
真命中可能被誤判成「只在導覽列」——**這個方向會漏東西**。
所以報告裡會把基準線的數字一起印出來，而且偵測到 soft-404 時會在 footer 警告。
看到警告就別信那次的「只在導覽列」分類。

**4. 只看伺服器端輸出的 HTML。**
如果某站改成用 JS 才渲染正文，這隻工具會看不到內容、把真命中判成「只在導覽列」。
目前 eeas.europa.eu 與 nato.int 都是伺服器端輸出，沒這個問題。

**5. 關鍵字要手動跟 eu_monitor 同步。**
`verify.js` 的 `SITES` 是從 `eu_monitor/index.html` 的 `SITES` 抄來的。
那邊改了這邊要跟著改，不然比對的是舊關鍵字。

## 還沒做的

**第①步：自動取得 Google 的結果清單。**

目前要自己把網址從結果頁複製進 `urls.txt`。

自動化的話就得爬 Google SERP，而那會撞 bot 偵測——2026-09-22 實測，
幾分鐘內約 15 條 `site:` 查詢就被出驗證頁。每天 3 條量很低，但不構成保證，
**且不得繞過挑戰**。

真要做的話，硬性要求是：**被擋時必須大聲失敗**，把整份報告標記為不完整，
絕不可以安靜地少回幾筆。否則就違反了「使用者無法分辨『今天真的只有三則』
和『你只給我看了三則』」這條。
